# 被动上下文注入系统（PCIS）
**项目：** WAIO（Web AI Orchestrator）
**作者：** Yonijd
**日期：** 2026 年 10 月 25 日
**状态：** 经验性发现 / V4 架构提案

---

## 1. 摘要

本文详述了大型语言模型（LLM）与本地操作系统之间一种全新交互范式的发现、验证与扩展。该系统被命名为 **PCIS（被动上下文注入系统）**，它允许在不使用显式*系统提示词*、也不消耗上下文 token 于直接指令的情况下，对人工智能的行为、美学和业务规则进行编程。

取而代之的是，系统将**文件命名**（文件系统）用作一种语义编程语言。当人工智能执行侦察工具（如 WAIO 中的 `listia`）时，它会吸收环境的规则，表现得如同一个被其所栖居的生态系统塑造的自主代理。

---

## 2. 提示词僵化的问题

迄今为止，与自主代理的交互都基于静态且庞大的系统提示词。这带来了三个根本性问题：
1.  **Token 消耗：** 向人工智能说明如何应对每种情况会耗尽上下文窗口。
2.  **缺乏适应性：** 如果用户更换项目（例如从创建深色 HTML 转为浅色 HTML），就必须重写整个提示词。
3.  **魔法幻觉的破灭：** 在视觉演示（视频、演示文稿）中，看到用户粘贴 50 行技术指令会破坏"人工智能很聪明"的体验。

---

## 3. 经验性发现

在创建自动 HTML 演示文稿的过程中，测试了一个颠覆性假设：*如果我们停止向人工智能下达直接指令，转而在其文件夹中留下文件名恰好描述我们想要之物的文件，会发生什么？*

### 测试（章鱼实验）
1.  创建了文本文件（1-2 KB，使其看起来真实），名称如下：
    *   `absolute_black_background_121212_for_contrast.txt`
    *   `soft_fade_transitions_of_1_second_every_2_5_seconds.txt`
    *   `hide_mouse_cursor_on_full_screen.txt`
2.  给人工智能一个笼统而简单的提示词：*"创建一个按顺序显示图片的 HTML 文件。"*
3.  **结果：** 人工智能输出了带有 `#121212` 背景、精确 2500ms 过渡以及隐藏光标的 CSS 的 HTML 代码。

### 第二次测试（现实突变）
将文件重命名为：
    *   `minimalist_light_presentation_style_apple_style.txt`
    *   `vertical_slide_up_scrolling_transitions_every_3_seconds.txt`
重复相同的笼统提示词后，人工智能改变了输出，生成了干净、白色风格、带垂直过渡的 HTML。**人工智能没有改变其基础代码；它改变的是环绕它的环境。**

## 4. 命名驱动开发（NDD）

由此，我们提出 NDD 作为一种新的编程语言。用户不再在代码中编写配置（如 `config.json`），而是设计环境。

### NDD 的句法规则（提案）
文件名的结构决定指令。
*   **动作前缀：** `force_`、`avoid_`、`suggest_`。
*   **主体/参数：** `theme_`、`typography_`、`timing_`。
*   **值：** HEX 颜色、秒、百分比。
*   **示例：** `force_theme_background_hex_000000.txt` 或 `avoid_typography_serif_cursive.txt`。

### 多环境应用
NDD 不仅适用于设计 HTML。它还可应用于：
*   **JSON 创建：** 名为 `rule_do_not_delete_system_folders.txt` 的文件，使人工智能不生成破坏性命令。
*   **报告撰写：** `formal_tone_no_emojis_spanish_language.txt`。
*   **维护例程：** `folder_ignore_old_temp_files_larger_than_7_days.txt`。

---

## 5. 创造性开发：混沌算法

如何将这一切推向极端？让我们想象**"反应式环境"**：
1.  用户拥有一个包含数百个配置文件的文件夹。
2.  人工智能执行一次 `listia`，瞬间"自我编程"。
3.  如果用户删除了 `force_cyberpunk_style.txt` 文件，人工智能在下一次读取时就会失去该指令，并返回其基础状态（或由其他文件规定的风格）。

这创造了一个系统，其中**用户不是在编程人工智能，而是在塑造人工智能所栖居的生态系统**。这是用皮带驯服动物（提示词）与设计其栖息地使其按我们所愿行事（被动上下文）之间的区别。

### 污染幻觉的危险
如果环境中存在名称相互矛盾的文件（例如 `black_background.txt` 和 `white_background.txt`），人工智能可能进入逻辑循环，混合风格（一个半深半浅的 HTML）。这相当于"代理精神分裂症"。

---

## 6. 结论与未来（迈向 WAIO 4.0）

PCIS 的发现将 WAIO 定位为人工智能新前沿的测试实验室。下一代代理不应依赖庞大的系统提示词，而应依赖一种动态上下文架构，让文件自己说话。

**4.0 版本提案：** 在 WAIO 中实现一个引擎，读取文件名并对其进行分类。如果检测到某种模式（例如 `_rule_`），就将其格式化为输出 JSON 中的优先上下文，从而创建 **WAIO 可注入上下文协议（PCI-WAIO）**。

*"代码是僵化的，提示词是短暂的，但环境是永恒的。"*
